# Agent Note: apply 会跑不止一次，替换要记引用计数

Status: implemented

## Problem

实测启动日志里插件那句出现了两轮——宿主会重放 `inject` 回调（服务重建、HMR 之类的路径）。

认证替换如果没有计数，「第一轮的清理」会把**还在生效的那一轮**一起拆掉：使用者看到的是「开关开着，
却仍然要重新换 token」。

## Decision

`src/browser-auth.ts` 用 `WeakMap<BrowserAuthLike, { original, refs }>` 记引用计数：

- 重复安装只加计数（句柄的 `patched` 为 false），最后一次 `restore` 才真正还原原型上的方法；
- 每个句柄的 `restore()` 幂等（内部 `released` 标志），重复调用不会多减计数；
- 从原型上取下来的原方法不 `bind`，还原时按同名字段写回去——绑过之后还原的是一个新函数，虽然行为
  等价，但会让「还原」看起来像改过。

注入行**不去重**：它是每次渲染现组装的常量，重复注册订阅方只会让同一行被 push 两次，而浏览器端
重复设置同一个标志位没有副作用。

## Alternatives considered

**假定宿主只调用一次。** 实测就是两轮；没有计数时卸载路径会拆掉别人还在用的那一轮。

**用模块级布尔「装过就跳过」。** 那无法区分「我自己替换的」与「宿主本来就是这样」，卸载时会错误地
把原方法写回去。

**给注入行也加去重。** 那要跨渲染持有状态，换来的只是「同一行不重复 push」这种没有可观察差别的
差别。

## Consequences

- `patch.patched` 让日志能分开「这次真的替换了」与「只加了引用计数」——排查时先看这两句。
- 开关关掉再打开不会累积替换：计数归零即还原，下一轮重新装。
