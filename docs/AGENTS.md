# AGENTS.md — 文档规范

本目录的四份文档各有一个家；同一条信息只在一处展开，别处放链接或一句话指过去。

| 文档 | 写什么 | 不写什么 |
| --- | --- | --- |
| [internals.md](internals.md) | 决策地图，以及没有记录承载的部分：跨插件的分工查表 | 决策依据与被否决的做法（→ [.agents/notes/](../.agents/notes/AGENTS.md)） |
| [development.md](development.md) | 怎么构建、怎么测、怎么装进一个 profile 手动验证 | 会与 `package.json` 脚本漂移的逐条清单 |
| [releasing.md](releasing.md) | 发布流程、包名与 scope、首版为什么必须手动发、三道硬校验 | 历史（→ git 与 PR） |
| 根 [AGENTS.md](../AGENTS.md) | 硬约束、提交信息口径、验证清单 | 故事、完整例子、能从链到的家读到的内容 |

放一份新文档之前先问它属于哪一行；都不属于就先想清楚它是哪一类，再回来改这张表。

## 写作规则

- **只写当前状态。** 历史留在提交、PR 与决策记录里；正文不写「原本是……后来改成……」，只点机制
  的名字。
- **手折行，按显示宽度大约 100 列断行**（中日韩字符算两列）：长链接、表格行、代码块与 YAML 头部
  随内容走，不为凑宽度硬断。
- **相对 Markdown 链接指向当下存在的文件**；历史引用用标签号或 PR 号。
- **数字只写实测值**：测试条数、量出来的值、产物字节数；机制写文件与函数名，不复述 diff。
- 中文单语。唯一的英文正文是 [README.en.md](../README.en.md)，它与 `README.md` 的键与结构保持
  对齐。
- 措辞调整与纯局部实现细节不需要新的文档段落，也不需要决策记录。

## 门禁

文档本身没有门禁。决策记录的格式由 `test/notes.test.ts` 核（在 `pnpm test` 里跑），本文件里那张表
与 [.agents/notes/AGENTS.md](../.agents/notes/AGENTS.md) 的分工要保持一致。
